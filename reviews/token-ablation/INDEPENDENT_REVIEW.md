# Independent review of the token-ablation evidence

I found no blocking numerical or interpretation issue in the checked-in findings and stage reports. This was a read-only audit of the retained records, summaries, frozen manifests, mechanism evidence, reporting code, and relevant product source. I did not run new Codex invocations, rerun the evaluators, or rerun the benchmark unit tests.

The retained records support the headline accounting: 36 scored invocations, all task-correct, with 35 valid measurements after one disclosed access-review exclusion. The availability stage contains 24 runs, 23 valid, and no GraphHarness retrieval calls among its 18 MCP-equipped runs. The guided stage contains 12 valid runs and two retrieval-using runs among nine MCP-equipped runs. The excluded native repair run remains visible with its usage and correctness but is absent from valid aggregates and paired comparisons.

I independently recomputed the arm totals from `runs.json` and matched them to each `summary.json` and report table. The guided full-versus-native differences are 47.2% for input and 34.8% for output. The individual values cited for the two retrieval runs and their native cells also match the retained records. For every run, input equals cached plus uncached input, total equals input plus output, and reasoning output is a subset of output. The reports therefore do not add cached input or reasoning output a second time.

The mechanism evidence covers all MCP-using scored runs. Its transcript hashes match the corresponding guided records, and its recorded outcomes agree with the audited transcripts: the polyglot bundle resolved no node and returned no source slices before a zero-result search, while the Java repair bundle selected `CouponPolicy.<init>` and returned two slices totaling 111 source characters. The cited implementation paths contain the described task-resolution, character-budgeting, and dual text/structured-content behavior. The findings correctly present these as observed mechanisms or plausible explanations rather than general causal estimates.

The interpretation is appropriately limited. It does not attribute availability-stage token differences to unused tools, and it does not infer a bundle effect from the guided stage, where only two of nine MCP-equipped runs followed the graph route and both later used shell. It discloses the reused small fixtures, two source corpora, uncontrolled provider caching, configured rather than attested model identity, unsealed host filesystem, observational tool-use subgroups, and the lack of production, large-repository, long-conversation, browser, lease, or multi-agent evidence. The matched-cell plotting code requires a valid, correct cell in every arm; the availability plot therefore uses five common cells rather than unequal arm totals.

The frozen manifests record identical product, runner, evaluator, and fixture identities across the two stages, and both regrade files report exact correctness-object matches for all 36 retained workspaces. Those are retained-artifact claims: I inspected their contents but did not independently reproduce the executions. Likewise, the statement that 12 benchmark unit tests pass was supplied by the completed test record and was not independently rerun in this audit.
